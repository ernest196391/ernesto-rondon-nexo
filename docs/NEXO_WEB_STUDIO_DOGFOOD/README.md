# NEXO Web Studio — Dogfood del Kit 01

## Objetivo

Antes de convertir el Cazador de Webs en un producto general, NEXO se usa a sí mismo como primer caso. Esta carpeta conserva la trazabilidad de cómo aplicamos la skill original a la página pública de NEXO y cómo la adaptamos al estándar NEXO Studio.

## Fuente

Kit aportado por el usuario: `01-kit-cazador-webs.zip`.

La skill fuente exige el patrón:

`reconocimiento → branding.json → diagnóstico de 5 problemas → reconstrucción → control de calidad → empaquetado/propuesta`.

NEXO conserva ese contrato, con dos adaptaciones deliberadas:

1. la web objetivo es nuestro propio producto y la fuente primaria es el repositorio canónico;
2. no se fuerza una estética 3D universal. Se reutiliza el lenguaje de motion cuando mejora la narrativa, pero la conversión, accesibilidad y claridad mandan.

## Estado

- [x] Fase 1 — reconocimiento del contenido y branding existente.
- [x] Fase 2 — diagnóstico con exactamente 5 problemas observables.
- [ ] Fase 3 — reconstrucción premium de la página pública de NEXO.
- [ ] Fase 4 — QA móvil, accesibilidad, build/lint/typecheck.
- [ ] Fase 5 — usar la propia reconstrucción como caso de prueba del Web Studio MVP.

## Regla de evidencia

No se inventan teléfonos, direcciones, reseñas, cifras, clientes, premios ni resultados. Si un dato no está en las fuentes canónicas, no entra en la nueva página.

## Resultado esperado

La home pública debe explicar NEXO en segundos, mostrar Studio como producto central, enseñar los especialistas como ofertas reales y hacer visible el dogfood de Web Studio sin convertir la interfaz operativa de `/studio` en una demo ornamental.
